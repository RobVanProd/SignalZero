## OSPFv2 — `src/engine/ospf.js`

Follows RFC 2328 (section numbers in the code comments). One process per router, area 0 plus non-backbone areas.

- **Interfaces join** through `network <addr> <wildcard> area <id>` or `ip ospf <pid> area <id>` on the interface (takes precedence; IOS shows "Attached via Interface Enable"). With overlapping network statements the **most specific** one decides the area, whatever the order typed; the running-config lists them most specific first and IOS logs `%OSPF-6-AREACHG` when a new statement moves a range to another area (current IOS behaviour; old IOS documentation still says "first match"). The statement address is normalised (host bits under the wildcard cleared).
- **Passive interfaces** (`passive-interface <if>`, `passive-interface default` + `no passive-interface <if>`) send and process no hellos but are advertised as stub networks.
- **Hello protocol (10.5):** hellos are multicast on the segment (they cross bridges/VLANs) and are subject to the receiving interface's **inbound ACL** as IP protocol 89 (`permit ospf any any` is accepted in ACLs); locally generated packets skip outbound ACLs. A hello is accepted only if area, hello interval, dead interval and (on broadcast networks) subnet mask match; a hello from our own router ID logs `%OSPF-4-DUP_RTRID_NBR`. An area-0 hello on an interface in another area logs `%OSPF-4-ERRRCV ... mismatch area ID, from backbone area must be virtual-link but not found` on that router only. `ip ospf hello-interval N` sets the dead interval to 4 × N unless `ip ospf dead-interval` is set.
- **Neighbour state machine (10.3):** DOWN → INIT (heard a hello) → 2WAY (found itself in the neighbour list) → EXSTART → EXCHANGE → LOADING → FULL, one second per database-exchange stage. 1-Way hellos drop a neighbour back to INIT. A DBD from the neighbour moves its view of us out of INIT at once (10.6).
- **Interface state machine (9.3) and DR/BDR election (9.4):** broadcast interfaces wait the **wait timer (= dead interval, 40 s)** before electing, unless a neighbour declares itself BDR, or DR with no BDR (BackupSeen). Priority, then router ID; priority 0 is never elected; an elected DR is not pre-empted by a better router joining later; adjacencies form only with the DR and BDR (10.4), so DROTHERs stay 2WAY with each other. `ip ospf network point-to-point` skips the election.
- **MTU (10.6):** a DBD advertising a larger MTU than the receiving interface's `ip mtu` is rejected: the lower-MTU side stays in EXSTART, the other side in EXCHANGE. `ip ospf mtu-ignore` (on the lower side) lets the exchange finish. A neighbour stuck this way is dropped after 125 s (`Too many DBD retransmitions`, Cisco's spelling; 25 retransmissions × 5 s) and the cycle restarts.
- **Timers:** hellos every hello interval; the dead timer per neighbour restarts with each accepted hello; an interface that goes down (link, shutdown, address/area/network-type change, leaving the process, becoming passive) drops its neighbours at once with `Interface down or detached`; a neighbour that simply stops (carrier cut beyond the NTE, far end made passive) is dropped after the dead interval with `Dead timer expired`. With `log-adjacency-changes` (IOS default) only transitions to FULL and to DOWN are logged; `log-adjacency-changes detail` logs every state with the IOS reason strings.
- **Router ID:** `router-id`, otherwise the highest up interface address when the process starts. A new router-id applies at once while the process has no neighbours; with neighbours IOS prints `% OSPF: Reload or use "clear ip ospf process" command, for this to take effect` and `clear ip ospf process` (confirmed with "yes" at `Reset ALL OSPF processes? [no]:`) applies it.
- **LSDB and flooding (12, 13):** every router keeps its own database per area. Router LSAs (type 1: point-to-point, transit and stub links, B and E bits), network LSAs (type 2, originated by the DR when it has a FULL neighbour), summary LSAs (type 3) and ASBR summaries (type 4) from area border routers (12.4.3; a router is an ABR when attached to area 0 and another area, as Cisco does per RFC 3509), and AS-external LSAs (type 5) for `default-information originate [always]` (metric 1, E2, tag = process ID; without `always` only while a non-OSPF default route is installed). New instances flood across adjacencies (sender FULL, receiver at least EXCHANGE); instances are compared by sequence number, then checksum, then MaxAge (13.1); a router that receives an old copy of its own LSA re-originates with a higher sequence number (13.4). Own LSAs refresh every 1800 s, others age out at 3600 s. Because each router keeps the copy it last received, a router whose neighbour vanished silently keeps using that neighbour's LSAs until its own dead timer fires — this is what failover timing depends on.
- **SPF (16):** Dijkstra per area with the two-way check (16.1 step 2b; equal cost: transit networks before routers), next hops per 16.1.1, inter-area routes from summaries (an ABR considers only backbone summaries, 16.2), external routes via the ASBR (16.4, E2 with forward metric). Path preference intra-area > inter-area > E1 > E2. **IOS SPF throttle:** first run 5 s after a database change, at least 10 s between runs. Cost = `ip ospf cost`, else reference bandwidth (default 100 Mb/s, `auto-cost reference-bandwidth` in Mb/s) ÷ interface bandwidth (`bandwidth` in kbit/s, else the type default: GigabitEthernet 1 000 000), truncated, minimum 1 — so every link of 100 Mb/s and faster costs 1 by default.
- **Routing table (`routing.js`):** OSPF routes are offered with administrative distance 110. Like the IOS RIB, each prefix keeps only the routes with the lowest administrative distance (connected 0, static 1 or its configured distance, OSPF 110): an AD-1 static hides the OSPF route for the same prefix, a floating static (e.g. AD 250) waits behind it. Forwarding then uses the longest matching prefix. Routes through an interface that went down are withdrawn at once; others change at the next SPF run. Statics may now resolve their next hop recursively through OSPF routes.

### Show and debug commands

`show ip ospf`, `show ip ospf neighbor [<if>]`, `show ip ospf interface [brief | <if>]`, `show ip ospf database`, `show ip route [ospf]` (`O`, `O IA`, `O E2`, `O*E2`, `[110/cost]`, `via <nh>, <age>, <if>`; filtered views keep the full-table subnet headers), `show ip route <addr>` for OSPF entries, `show ip protocols` (now simulated; with no protocol only the NSF banner), running-config `router ospf` block and interface `ip ospf …` lines, `debug ip ospf hello|adj`, `undebug all`, `show debugging`. Debug output goes to the logging buffer (`show logging`).

## SSH in-band management — `src/cli/ssh.js`, `src/cli/index.js`

- **Clients:** IOS `ssh -l <user> <ip>` (also `ssh -v 2 -l …`), Windows 11 and Ubuntu `ssh user@host` / `ssh -l user host` (OpenSSH). The connection is a real TCP 22 probe through the simulated network, so routing, PAT, inbound ACLs and the return path all matter. Timeouts, resets and unreachable networks print the client's own wording (table below).
- **Servers:** IOS routers whose vty lines allow SSH (`transport input ssh`), with `access-class` checked against the source address the router sees after NAT (the branch refuses the internet: PAT makes a NOC session arrive as 198.51.100.2); Ubuntu hosts running `ssh`; BRANCH-PC (Windows OpenSSH Server). Lab credential `admin` / `nightshift` (privilege 15 on IOS, so the session starts at `#`).
- **Nested sessions:** the console's session object carries the connection (`sess.ssh = { …, sess: <remote session> }`), possibly several hops deep (Windows → Ubuntu → BRANCH-RTR → EDGE-RTR works). Commands run on the innermost device and are logged with that device as `host` (and `via` the console). `exit`/`logout` on the remote side returns to the previous hop with the client's closing message. The password line is masked in the event log, and `execute()` returns `secret: true` while a password prompt is pending.
- **Lost paths:** before each command the path of every hop is probed again; if a change on the far end cut it (for example `passive-interface g0/0` on BRANCH-RTR over a session that relies on OSPF), the session drops with a trainer note.

## Known simplifications (do not teach these as fact)

- One OSPF process per router. Not modelled: authentication (`area … authentication` and `ip ospf authentication…` answer with a labelled training-image note), stub/NSSA areas, area ranges and summarisation, virtual links, redistribution other than the default route, NBMA/point-to-multipoint network types, loopback interfaces, equal-cost multipath (one best path; ties broken deterministically), `ip ospf dead-interval minimal`, BFD.
- Timing: after an interface parameter change, or when an interface's DR/BDR view changes, the next hello goes out within a second (IOS restarts the timer; the exact behaviour is unverified). Database exchange takes one second per stage regardless of database size; flooding across adjacencies is instantaneous; LSA retransmission, MinLSInterval and MinLSArrival are not modelled; the SPF throttle is a fixed 5 s initial delay and 10 s hold (IOS backs off exponentially up to the maximum wait, which defaults to the same 10 s).
- LSA checksums are a deterministic stand-in with the right format, not the Fletcher checksum of an encoded LSA. Interface IDs and `Index` values in `show ip ospf interface` are synthetic. `show ip ospf` prints the IOS 15 default timer lines as IOS does; only the behaviour above is simulated.
- Interface bandwidth is the configured `bandwidth` or the interface-type default; whether IOS lowers BW to a negotiated 100 Mb/s on GigabitEthernet is unverified, so the simulator does not.
- Neighbour roles (DR/BDR/DROTHER) in `show ip ospf neighbor` come from this router's view of the segment.
- The carrier is a single transparent bridge: cutting the carrier tail (`carrier-b`) brings BRANCH-RTR's port down while EDGE-RTR keeps link to the NTE (no link-loss forwarding), which is the realistic asymmetric case; CDP does not cross the carrier.
- Debug output appears only in the logging buffer, not asynchronously on the console.
- SSH: no key exchange or algorithm negotiation (real IOS 15 images offer only `ssh-rsa` host keys, which OpenSSH 8.8+ refuses by default — a real-world pitfall not shown here), no first-connection host-key prompt (known_hosts assumed populated), no session timeouts. A session whose path breaks drops at the next command; real clients freeze until TCP gives up. On Ubuntu SSH sessions the privilege model is not simulated (commands behave as for root). OpenSSH options are a subset (`-l`, `-p`, `-o`, flags ignored). The password is visible in the terminal unless the UI masks input while `secret` is true.
- `ssh <host>` without `-l` on IOS answers with a labelled note instead of guessing the IOS behaviour.

## Notes for integration

- `execute()` returns `secret: true` while a password prompt is pending: the terminal should mask the next input. The terminal's `?` and Ctrl+Z handling read `c.sess.os`; for nested sessions use `activeSession(sess).os` (exported from `src/cli/index.js`), and `activeDevice(sess)` for labels.
- The branch devices have no station or 3D placement yet (BRANCH-RTR and BRANCH-PC are reached over SSH); `CARRIER` is not in the cables' offsite set and EDGE-RTR Gi0/3 has no anchor, so those links are not drawn. The city has no `branch` district yet.
- `EXPANSION_PLAN.md` names EDGE-RTR Gi0/2 for the carrier; this build uses a new Gi0/3 (Gi0/2 stays the spare behind P02, per the task brief).
- M12's `outcome` has no `compare` table (the debrief screen's table is hard-wired to the M06 riser columns); it reports `method` and `detection` (dead interval in seconds).

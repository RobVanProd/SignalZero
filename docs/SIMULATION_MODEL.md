# Simulation model

One deterministic engine (`src/engine/`) is the single source of truth for every console, the 3D world, the HUD and all win conditions. State is plain JSON (saved to `localStorage`, cloned for challenge proofs). Randomness comes from a seeded PRNG stored in the state, so a run can be replayed.

## Layer 1 — `link.js`

- A link is up when both ports are administratively up, not err-disabled, powered, of compatible kind (an RJ-45 console port never links with Ethernet), on matching media, and the cable is not cut.
- Auto-negotiation follows the IEEE 802.3 clause 28 behaviour that matters for troubleshooting: a 10/100 port with **both** speed and duplex hard-set stops negotiating; its auto-negotiating partner falls back to **parallel detection**, learns the speed and assumes **half duplex**. That produces a duplex mismatch. 1000BASE-T is treated as always negotiating. Hard-set speeds that differ cannot link.
- Mismatch effects: the half-duplex side accumulates collisions/late collisions, the full-duplex side CRC errors and runts; CDP logs `%CDP-4-DUPLEX_MISMATCH`. Loss/jitter on the link are illustrative constants (≈6% loss per traversal under load), not a physical model.

## Layer 2 — `switching.js`

- Access/trunk ports, allowed VLAN lists, native VLAN tagging, VLAN database membership (IOS auto-creates a VLAN on `switchport access vlan`).
- **Spanning tree per VLAN (PVST+ / Rapid PVST+):** root bridge = lowest (priority + VLAN, MAC); root port = lowest (root path cost, designated bridge ID, designated port ID, own port ID); one designated port per segment; others alternate/backup. Path cost uses the 802.1D-1998 short values (1G = 4). Switches with STP disabled for a VLAN, and unmanaged bridges, are transparent (they flood BPDUs), so they behave as shared segments between STP speakers.
- **Timers:** 802.1D blocking → listening (15 s) → learning (15 s) → forwarding. PortFast edge ports (`spanning-tree portfast`, or `portfast trunk` on a trunk to a router/server) forward immediately. Rapid PVST+ is rapid only where 802.1w allows it: a new root port forwards in ~1 s (local decision), and a designated port forwards in ~1 s only through proposal/agreement, i.e. on a point-to-point (full-duplex) link to another Rapid PVST+ switch. Toward a router, a host without PortFast, a legacy PVST+ switch or a shared (half-duplex) link a Rapid PVST+ port falls back to discarding (15 s) → learning (15 s) → forwarding. If the neighbour turns RSTP on later, the handshake cuts the timer short. `show spanning-tree` reports `P2p`/`Shr`, `Edge` and `Peer(STP)` (legacy neighbour). Enabling STP on a VLAN restarts its ports from blocking.
- **Root macro:** `spanning-tree vlan N root primary` writes 24576 if that wins the election, otherwise 4096 below the current root's priority; `root secondary` writes 28672.
- **Loops:** after STP, a VLAN whose forwarding graph contains a cycle is in a broadcast storm: its links saturate (≈97% loss for that VLAN, ≈55% for other VLANs sharing the links), switch CPU reads 99%, and `%SW_MATM-4-MACFLAP_NOTIF` is logged.
- **Flooding** computes exactly which endpoints a frame reaches and the port-by-port path, which also drives ARP, the MAC address table and the packet animation.
- **DHCP snooping** drops server-side DHCP messages arriving on untrusted ports in snooped VLANs. By default it inserts option 82 into client requests from untrusted ports while leaving giaddr 0.0.0.0; an IOS relay (`ip helper-address`) drops such a request unless the receiving interface has `ip dhcp relay information trusted` (or the router `ip dhcp relay information trust-all`), or the switch has `no ip dhcp snooping information option`.
- **PVID check (native VLAN mismatch):** PVST+ and Rapid PVST+ send an SSTP BPDU on the native VLAN carrying the sender's VLAN id. When the two ends of a switch-to-switch trunk disagree on the native VLAN, the receiving switch puts the port into PVID-inconsistent state for both VLANs (`show spanning-tree`: `BKN*`, `*PVID_Inc`), logs `%SPANTREE-2-RECV_PVID_ERR` and `%SPANTREE-2-BLOCK_PVID_LOCAL/PEER`, and unblocks (`%SPANTREE-2-UNBLOCK_CONSIST_PORT`) when they match again. So untagged frames do not leak between the two VLANs. With STP disabled for the VLAN nothing checks, and the leak is real.
- **BPDU guard** err-disables an edge port that hears an STP speaker over a live link. Recovery is `shutdown` then `no shutdown` (`no shutdown` alone leaves the port err-disabled); errdisable auto-recovery is not modelled.

## Layer 3 — `routing.js`, `trace.js`

- Host addressing: static, DHCP lease, or APIPA (Windows only, after a failed exchange). Hosts route on-link or via the default gateway; no gateway gives Windows `PING: transmit failed. General failure.`
- Router tables: connected + local routes from up/up interfaces; static routes installed only if the next hop resolves through a connected (or recursively through another static) route — "configured is not installed". Longest prefix, then administrative distance. A static route naming only an exit interface (`ip route 0.0.0.0 0.0.0.0 g0/0`) is installed while the interface is up, shows as "is directly connected", and makes the router ARP for each destination; that works only if the next router answers proxy ARP. **Choice:** ISP-PE (the provider edge) has proxy ARP disabled, as providers commonly do on customer-facing interfaces, so an interface-only default route over the Ethernet WAN fails with "encapsulation failed" — use a next-hop address (or interface plus next hop). New IOS subinterfaces and the unconfigured spare Gi0/2 keep the IOS default (proxy ARP on); the district's configured interfaces have `no ip proxy-arp`.
- **ACLs:** Cisco semantics — top-down, first match wins, implicit deny at the end, wildcard masks, standard (source only) and extended (protocol, source/destination, `eq/neq/lt/gt/range` ports, ICMP message names, `established`, `log`). An ACL that is applied but not defined permits everything. TCP segments carry flags: a probe's opening segment is a SYN, replies are SYN-ACK or RST, so `established` (ACK or RST set) passes replies to connections opened from inside but not new inbound connections.
- **PAT:** `ip nat inside source list … interface … overload`; the reply is un-translated on the outside interface. ICMP errors (time exceeded, unreachables) are un-translated using the header they embed, so traceroute and port-unreachable work through PAT. Locally generated router traffic (`ping … source g0/1.10`) is not translated. Missing NAT produces a real asymmetric failure (request delivered, reply has no route back).
- **Packet walk (IOS order of operations):** every hop does ARP in the egress broadcast domain, inbound ACL, NAT outside→inside, TTL decrement (time-exceeded at TTL 1), route lookup (ICMP net-unreachable if none), NAT inside→outside, outbound ACL, next hop. So an outbound ACL on the NAT outside interface matches the inside-global (translated) source, and an inbound ACL there matches the inside-global destination. A router answers UDP to one of its own addresses with port unreachable (unless `no ip unreachables`) and TCP with RST. Replies are traced independently, so asymmetric problems surface. Initial TTL: Windows 128, Linux 64, IOS 255.

## Services — `services.js`, `parsers/`

- **ISC DHCP:** `dhcpd.conf` subset (subnet/netmask, range, routers, DNS, domain, lease times, host/fixed-address) with dhcpd's own error wording; refuses to start without a subnet declaration for its interface. Scope selection by `giaddr` for relayed requests. DORA, INIT-REBOOT (`ipconfig /renew` with an existing lease → ACK or NAK → DORA), pool exhaustion (`no free leases`), relay via `ip helper-address`, rogue servers answering first on-segment. Journal lines follow dhcpd's format. The `authoritative;` statement is honoured: an authoritative server NAKs a request for an address on the wrong network (`DHCPREQUEST for … via …: wrong network.` then `DHCPNAK on … to … via …`); a non-authoritative one stays silent (`…: ignored (not authoritative).`). Valid syntax the simulator does not act on (`pool { }`, `range dynamic-bootp`, `ping-check`, `one-lease-per-client`, `log-facility`, common options) is accepted and ignored rather than rejected.
- **DHCP client states (RFC 2131):** a bound client renews at T1 (half the lease) with a REQUEST unicast to the server that issued the lease, sent from the leased address through its gateway. Inbound ACLs, routing and DHCP snooping apply to that unicast like any other packet. If it fails, the client retries and at T2 (7/8 of the lease) broadcasts a rebinding REQUEST that relays forward. At expiry it starts over with DORA. A link change or reboot makes a client ask for its remembered address again (INIT-REBOOT broadcast), which an authoritative server NAKs on the wrong network. Windows `ipconfig /renew` with a valid lease sends the unicast renewal; when that gets no answer it reports "unable to contact your DHCP server. Request has timed out." and keeps the unexpired lease. `ipconfig /release` then `ipconfig /renew` starts over with DORA. Consequences the incidents teach: a Wi-Fi client behind an AP whose switch port moved to another VLAN keeps its old lease (no link change) until released or expired (M05). Cameras whose gateway was renumbered fail their T1 renewal and recover only at T2 unless their PoE port is bounced (M08). An inbound ACL that denies guests → inside also drops their unicast renewals unless DHCP (`udp eq bootps`) is permitted first (M05).
- **BIND:** zone-file subset (`$TTL`, `$ORIGIN`, SOA/NS/A/CNAME/MX/TXT/PTR, parentheses, relative names) with `named-checkzone`-style errors; authoritative answers (AA) for loaded zones, recursion via forwarders when reachable, SERVFAIL otherwise; edits apply only on `rndc reload` (or `systemctl reload named`). A zone that fails to reload keeps serving its last good copy and named logs `dns_rdata_fromtext: …`, `zone …/IN: loading from master file … failed: …` and `not loaded due to errors.`; `rndc reload` itself still prints "server reload successful" (`rndc reload <zone>`: "zone reload queued"). After a start/restart there is no old copy: names in a primary zone that did not load get SERVFAIL and are never forwarded. Zone files accept TTL units (`1D`, `1h30m`, SOA timers like `1h`); a zone without `$TTL` uses the SOA MINIMUM with BIND's warning `no TTL specified; using SOA MINTTL instead`.
- **DNS clients:** a DNS server whose host is up but has nothing on UDP 53 answers with ICMP port unreachable, which `dig`/`nslookup` report at once as "connection refused" (Windows nslookup: "No response from server"); silence (path down, filtered) is a timeout. This mirrors curl's refused (TCP RST) vs timed out.
- **Windows DNS client:** positive answers cached for the record TTL; `ping`/`curl` use the cache, `nslookup` asks the server directly; `ipconfig /displaydns` and `/flushdns`. Single-label names get the connection-specific suffix.
- **HTTPS:** name resolution → TCP connect (SYN-ACK, RST = refused, silence = timeout) → certificate name check (Schannel/OpenSSL style error 60) → nginx virtual host response. Host firewalls can drop ports.
- **Voice quality:** a simplified ITU-T G.107 E-model turns simulated delay, jitter and loss into MOS.

## Time

The engine has a simulated clock (`advance(dt)`): STP timers, DHCP lease timers (T1 renewal, T2 rebinding, expiry) for every leased host and camera, Windows APIPA retries every 300 s, interface counters, syslog for storms, CDP and PVID inconsistency. The game runs it in real time; `T` fast-forwards ×8.

## Known simplifications (do not teach these as fact)

- DHCP: the server ignores option 82 contents; lease times come from dhcpd.conf (the camera scope uses 10 minutes so T1/T2 behaviour shows within a shift); T1/T2 retries follow a simplified back-off (half the remaining time, at least 60 s); there is no DHCPDECLINE / ARP conflict check.
- Command shells are subsets; output imitates real formats closely but is not byte-identical, and some strings vary between real software versions (notably curl error wording).
- ACL denies are silent drops (as if `no ip unreachables`), even though IOS sends ICMP administratively-prohibited by default. ICMP error rate limiting is not modelled.
- ARP failure at a router is a silent drop. No ARP cache timing, no gratuitous ARP / duplicate address detection.
- No TCP state machine, windowing or retransmission model; HTTP is request/response only. TCP flags exist only as far as `established` needs them (SYN out, SYN-ACK/RST back).
- Windows negative DNS caching is not modelled.
- STP: no max-age expiry for indirect failures, no TCN/MAC flush timing, no MST, no `spanning-tree link-type` override; the RSTP proposal/agreement handshake is modelled as ~1 s rather than sub-second. A port configured for PortFast while already discarding waits for its timers (it becomes edge on the next link-up).
- IOS CLI: valid commands the image does not simulate (e.g. `show spanning-tree interface`, `show ip protocols`, `show ip nat statistics`) answer with a labelled "training image" note instead of output.
- Loss, latency, jitter and MOS are illustrative, not derived from real queueing.
- Not modelled at all: IPv6, dynamic routing, wireless RF, VPN, NTP, SNMP/NetFlow, cloud, link aggregation, QoS.
